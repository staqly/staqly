These are the tools an agent sees once staqly is [connected over MCP](/mcp). You rarely call
them by hand — the agent picks them from your request — but this page tells you what each one
can do, which inputs it takes, and which [scope](/api/authentication#scopes) an API key needs
for it in cloud mode.

## Example: gate an action on approval

The most common sequence, with the arguments an agent sends:

<Steps>
<Step>
### Store the proposal: `create_item`

```json
{ "collection": "Deploys", "title": "Run the users migration", "content": "ALTER TABLE users ADD COLUMN last_seen_at timestamptz", "expires_in": "24h" }
```

The item is created as `pending` and shows up in the Inbox.
</Step>
<Step>
### Wait for the decision: `await_decision`

```json
{ "item_id": "itm_oalirbz67y4m4cqxq5dw" }
```

Returns `decided: false` on timeout — call it again to keep waiting. Act only when the item's
status is `approved`. Many clients give up on a tool call after 60 seconds (Claude Code and Codex
by default), so keep `timeout_seconds` under that (the default is 45) and call again, or raise the
client's limit first (Claude Code: `MCP_TOOL_TIMEOUT=360000`; Codex: `tool_timeout_sec` on the
server).
</Step>
<Step>
### Record what happened: `report_result`

```json
{ "item_id": "itm_oalirbz67y4m4cqxq5dw", "status": "completed", "result": { "rows": 1200 } }
```
</Step>
</Steps>

A full walkthrough: [Gate a risky agent action on human approval](/cookbook/approval-gate).

## Conventions

- Scopes only matter in **cloud mode** (with an API key); in local mode every tool is
  available.
- Tools marked *read-only* are annotated as such for clients that care.
- Collection inputs accept an ID (`col_qjuybkx6355nz4no6pqk`) **or** the exact name.
- Every REST operation has a tool, and both go through the same authorization checks. Only
  the browser flows (sign-in, sign-out, setup, redeeming a device link, decision links),
  recovery key rotation (dashboard session only), the agent list (`/v1/agents`), the list of
  workspace exports (`GET /v1/workspace/exports`) and writing a new summary
  (`POST /v1/items/{id}/summarize`) have none.
- Tools marked *destructive* delete or invalidate something (data, a key, a secret).
- A suspended workspace (unpaid Pro period) can call read-only tools plus `revoke_session`,
  `revoke_api_key`, `create_device_link`, `start_workspace_export`, `choose_free_plan`,
  `start_billing_checkout`, `open_billing_portal`, `delete_workspace` and `purge_item`; other tools answer with `plan_expired`, like REST.

## Collections

### `list_collections`
List collections with item counts per status. *Read-only* · `collections:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `include_archived` | boolean | No | Include archived collections |

### `get_collection`
Get a collection by ID or name, including its configured actions. *Read-only* · `collections:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | <Required /> | ID or exact name |

### `create_collection`
Create a collection (e.g. "Instagram Avatar"). New collections get every catalog action
*regenerate, publish, retry, archive* (publish and archive are always on; `update_collection` changes the flow). · `collections:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `name` | string | <Required /> | Collection name, shown in the dashboard sidebar |
| `description` | string | No | Short description shown under the name |
| `default_view` | string | No | `gallery`, `table` or `list`. Kept for API compatibility only: the dashboard always shows a collection as a table |

### `update_collection`
Update a collection's name, description, icon, color, default view or action flow, or archive or unarchive it.
Omitted inputs stay unchanged; archiving an archived collection (or unarchiving an active one) is a conflict. · `collections:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | <Required /> | ID or exact name |
| `name` | string | No | New name |
| `description` | string | No | New description |
| `icon` | string | No | Icon name shown in the sidebar |
| `color` | string | No | Accent color, e.g. `#7c3aed` |
| `default_view` | string | No | `gallery`, `table` or `list`. Kept for API compatibility only; the dashboard ignores it |
| `actions` | object[] | No | Replaces the flow: `[{name, allowed_statuses?, auto_run?}]` from the [catalog](/automation/custom-actions#the-catalog) (`regenerate`, `publish`, `retry`, `archive`). Publish and archive are always added; `auto_run` (publish only) starts publishing on approval |
| `archived` | boolean | No | `true` archives the collection, `false` restores it |

### `delete_collection`
Permanently delete a collection and all its items. *Destructive* · `collections:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | <Required /> | ID or exact name |
| `confirm` | string | <Required /> | Must be exactly the collection name, e.g. `Deploys` |

## Items

### `list_items`
List items, optionally filtered; newest first. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | No | ID or name |
| `status` | string | No | `draft`, `pending`, `approved`, `rejected`, `expired`, `processing`, `completed`, `failed`, `archived` |
| `type` | string | No | `image`, `video`, `text`, `link`, `json`, `file` |
| `decision` | string[] | No | Any of `pending`, `approved`, `rejected`, `expired` (archived items are left out), or `archived` |
| `run` | string[] | No | Any of `none`, `processing`, `completed`, `failed` |
| `tag` | string[] | No | Items carrying any of these tags |
| `sort` | string | No | `created_desc` (default), `created_asc`, `updated_desc`, `decided_desc`, `title_asc` |
| `limit` | integer | No | Default 50, max 200 |
| `cursor` | string | No | `next_cursor` from a previous call |

### `get_item`
One item with content, metadata, media and status. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | `itm_oalirbz67y4m4cqxq5dw` |

### `create_item`
Add an item to a collection. Items default to `pending` so they show up for review. `image` and
`video` items need `media_base64`, `media_id` or a `url`. · `items:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | <Required /> | ID or exact name |
| `title` | string | No | Short title shown in the Inbox |
| `type` | string | No | Inferred when omitted |
| `content` | string | No | Text body, caption, or a JSON string |
| `url` | string | No | External http(s) URL (a link or externally hosted media) |
| `media_base64` | string | No | Base64-encoded file to upload (image, video, PDF or any other file) |
| `media_filename` | string | No | File name for `media_base64`, e.g. `avatar.png` |
| `media_id` | string | No | A file already uploaded with [`upload_media`](#upload_media) (`med_...`), instead of `media_base64` |
| `metadata` | object | No | Arbitrary JSON: prompt, model, seed, score |
| `status` | string | No | Initial status: `pending` (default), `draft`, or `approved`/`rejected` with `items:review` |
| `tags` | string[] | No | Labels, up to 20 |
| `source` | string | No | Producer identifier; defaults to the MCP client's name (e.g. `Claude Code`) |
| `external_ref` | string | No | Your own reference ID |
| `expires_in` | string | No | Undecided items expire after this duration, e.g. `24h` |
| `editable` | string[] | No | Fields a reviewer may edit before approving: `title`, `content`, `url`, `metadata`, `metadata.<key>` |

### `update_item`
Update fields or status (e.g. `processing`, `completed`, `failed`). Approve/reject must use
`approve_item` / `reject_item`. · `items:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID (for example `itm_oalirbz67y4m4cqxq5dw`) |
| `title` | string | No | New title; omitted fields stay unchanged |
| `content` | string | No | New text body, caption or JSON string |
| `url` | string | No | New external http(s) URL |
| `media_id` | string | No | Replace the file with one uploaded with `upload_media` (`med_...`) |
| `external_ref` | string | No | New reference ID of your own |
| `metadata_patch` | object | No | Keys to set; a `null` value removes the key |
| `tags` | string[] | No | Replaces the item's tags, in any status (no new version) |
| `status` | string | No | `draft`, `pending`, `processing`, `completed`, `failed`, `archived` (a run only after a decision) |
| `expected_version` | integer | No | Fail with a conflict if the item changed since this version |

### `search_items`
Full-text search over title, content and metadata with optional filters — e.g. images approved
yesterday. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `query` | string | No | Text to find |
| `collection` | string | No | Collection ID or exact name |
| `status` | string | No | Item status, e.g. `approved` |
| `type` | string | No | `image`, `video`, `text`, `link`, `json` or `file` |
| `created_after` | string | No | `YYYY-MM-DD` or RFC 3339, inclusive |
| `created_before` | string | No | `YYYY-MM-DD` or RFC 3339, exclusive |
| `decided_after` | string | No | Lower bound of the approval or rejection time, inclusive |
| `decided_before` | string | No | Upper bound of the approval or rejection time, exclusive |
| `limit` | integer | No | Maximum results (default 50, max 200) |

### `get_item_history`
The event history (decisions, edits, actions) and prior versions of an item. *Read-only* ·
`items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID |

### `get_item_versions`
The prior versions (snapshots) of an item, newest first. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID, e.g. `itm_oalirbz67y4m4cqxq5dw` |

### `delete_item`
Delete an item. Its events stay in the activity log; use `purge_item` to erase them too.
*Destructive* · `items:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID |

### `purge_item`
Erase an item together with its versions, events, pending webhook deliveries and media no
other item uses, e.g. to remove personal data. One content-free `item.purged` event records
it. *Destructive* · `admin`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID |

## Review

### `list_pending_approvals`
Items waiting for review across all collections, oldest first. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | No | Collection ID or name; omit for all collections |
| `type` | string | No | e.g. `image` |
| `limit` | integer | No | Maximum results (default 50, max 200) |

### `approve_item`
Approve a pending item, optionally editing title/content first. · `items:review`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID |
| `feedback` | string | No | Optional note stored with the decision |
| `title` | string | No | New title, applied before approving (subject to the item's `editable` list) |
| `content` | string | No | New content or caption, applied before approving (subject to the item's `editable` list) |
| `expected_version` | integer | No | The item's `version` you reviewed; if it changed since, the call fails with a conflict and nothing is applied |

### `reject_item`
Reject a pending item with feedback explaining why. · `items:review`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID |
| `feedback` | string | <Required /> | Sent to automations so they can regenerate |
| `follow_up` | string | No | Run this action next with the same feedback, e.g. `regenerate` |
| `expected_version` | integer | No | The item's `version` you reviewed; if it changed since, the call fails with a conflict and nothing is applied |

### `list_available_actions`
Actions the caller can run on an item in its current status. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID |

### `execute_custom_action`
Run a catalog action the item's collection enables, such as *regenerate* or *publish*. It records an event and notifies
webhooks; external automations do the actual work. · `actions:execute`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID |
| `action` | string | <Required /> | From `list_available_actions` |
| `feedback` | string | No | Required by some actions (e.g. regenerate) |
| `payload` | object | No | Extra JSON passed to webhook receivers |

### `execute_bulk_action`
Run one action on up to 100 items. Each item succeeds or fails on its own; the result lists
`ok`, `error` and the updated item per ID. · `items:review` for `approve` / `reject`,
`actions:execute` for the other actions

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_ids` | string[] | <Required /> | 1 to 100 item IDs, e.g. `["itm_oalirbz67y4m4cqxq5dw"]` |
| `action` | string | <Required /> | `approve`, `reject` or a collection action such as `publish` |
| `feedback` | string | No | Note stored with each decision; required by `regenerate` and expected with `reject` |
| `payload` | object | No | Extra JSON passed to webhook receivers |

## Activity log

### `list_events`
The activity log (items created, approved, rejected, actions run, settings changed), newest
first. Without `admin`, the [audit events](/api/events#audit-events) are left out.
*Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | No | Only events about this item |
| `collection` | string | No | Collection ID or name |
| `type` | string | No | Event type, e.g. `item.approved` |
| `actor_type` | string | No | `session`, `api_key`, `local` or `system` |
| `actor_id` | string | No | Only events by this actor, e.g. an API key ID (`key_r7y65khtqa23kj4btvur`) |
| `type_prefix` | string | No | Event type prefix, e.g. `webhook.` |
| `from` | string | No | `YYYY-MM-DD` or RFC 3339, inclusive |
| `to` | string | No | `YYYY-MM-DD` or RFC 3339, exclusive |
| `limit` | integer | No | Default 50, max 200 |
| `cursor` | string | No | `next_cursor` from a previous call |

### `export_events`
Export the activity log as NDJSON or CSV text, oldest first. The output is capped at 1 MiB;
when `truncated` is `true`, narrow `from` / `to` to get the rest. Without `admin`, the
[audit events](/api/events#audit-events) (API keys, sessions, recovery key, devices) are left
out, as in `list_events`. On the Free cloud plan it answers `plan_limit_exceeded` (no data
export). *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `format` | string | No | `ndjson` (default) or `csv` |
| `from` | string | No | `YYYY-MM-DD` or RFC 3339, inclusive |
| `to` | string | No | `YYYY-MM-DD` or RFC 3339, exclusive |
| `type` | string | No | Exact event type, e.g. `item.approved` |
| `type_prefix` | string | No | Event type prefix, e.g. `item.` |
| `actor_type` | string | No | `session`, `api_key`, `local` or `system` |
| `actor_id` | string | No | Actor ID, e.g. an API key ID like `key_7dq2m5vxk3pzr8hn4wty` |
| `collection` | string | No | Collection ID or name |
| `item_id` | string | No | Only events about this item |

Returns `format`, the number of `events`, `truncated` and the export text in `content`, one
event per line.

## Approval gate

### `await_decision`
Wait until a human approves or rejects an item (or it expires). Returns `decided: false` on
timeout — call again to keep waiting. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Item ID to wait for |
| `timeout_seconds` | integer | No | Default 45, max 300. Keep it under your client's tool timeout (often 60 s) |

Returns `{ "decided": true, "item": { "id": "itm_oalirbz67y4m4cqxq5dw", "status": "approved" } }`.

### `report_result`
After an approved item was acted on (e.g. published), record the outcome. · `items:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `item_id` | string | <Required /> | Must be `approved` or `processing` |
| `status` | string | <Required /> | `completed` or `failed` |
| `result` | object | No | Outcome details, stored in `metadata.result` (e.g. `{"post_url": "https://instagram.com/p/C9xYz"}`) |
| `error` | string | No | Failure reason, stored in `metadata.error` |

See [Gate a risky agent action on human approval](/cookbook/approval-gate).

### `unarchive_item`
Bring an archived item back where it was: back to review (`pending`) if it was archived while waiting for a
decision, else its run (published, failed...) if one ran, else its decision. Bringing back `approved` or
`rejected` also needs `items:review`. `item_id`. · `items:write`

### `get_flow`
Where items are and how they moved: item counts per state (decision, run, the action that started it, archived)
and event counts per type in the last 24 hours. Optional `collection`. *Read-only* · `items:read`

### `list_tags`
The workspace's item tags with how many items carry each, most used first. Use them with `list_items` (`tag`)
or `update_item` (`tags`). *Read-only* · `items:read`

### `list_requested_work`
Items a person asked your automation to work on (Publish, Regenerate, Retry...) that wait for a result: their
`run` is `processing` and `run_action` says what was asked. Without webhooks, poll this, do the work, then call
`report_result`. Oldest first. *Read-only* · `items:read`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | No | Collection ID or name |
| `action` | string | No | Only work started by this action, e.g. `publish` |
| `limit` | integer | No | Default 50, max 200 |

## Watchers

### `list_watchers`
Watchers with their status, last run and errors. *Read-only* · `watchers:manage`

No inputs.

### `create_watcher`
Watch any RSS/Atom feed (`rss`) or a web page or JSON endpoint for changes (`url_diff`); new

`watchers:manage`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `name` | string | <Required /> | Watcher name |

| `exclude_keywords` | string[] | No | Skip entries containing any of these words |
| `every` | string | No | Check interval, e.g. `30m` or `6h` |

### `get_watcher`
One watcher with its status, last run and errors. *Read-only* · `watchers:manage`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `watcher_id` | string | <Required /> | Watcher ID, e.g. `wat_5k2nq8rx7bvm3dz4hcye` |

| Parameter | Type | Required | Description |

| `collections` | string[] | No | IDs or names; replaces the list of collections |
| `status` | string | No | `active` (resume) or `paused` |
| `keywords` | string[] | No | Only entries containing one of these words |
| `exclude_keywords` | string[] | No | Skip entries containing any of these words |
| `every` | string | No | Check interval, e.g. `30m` |

### `delete_watcher`
Delete a watcher; items it created stay. *Destructive* · `watchers:manage`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `watcher_id` | string | <Required /> | Watcher ID |

### `run_watcher`
Check a watcher's source now instead of waiting for the next interval. Returns the run's

| Parameter | Type | Required | Description |
|---|---|---|---|

### `get_workspace`

### `rename_workspace`
Rename the workspace and/or set how long items may stay `processing` before they fail. · `admin`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `name` | string | No | New workspace name |
| `processing_timeout_seconds` | integer | No | How long an item may stay `processing` before it fails, 60 to 86400 seconds |

### `delete_workspace`
Permanently delete the workspace and everything in it (cloud mode only; local mode answers with a conflict). As in REST, this
needs a signed-in dashboard session, so API keys get a `forbidden` error. *Destructive*

| Parameter | Type | Required | Description |
|---|---|---|---|
| `confirm` | string | <Required /> | Must be exactly the workspace name |

### `start_workspace_export`
Start a ZIP export of the whole workspace (items, media, events). Poll
`get_workspace_export` until the status is `ready`. · `admin`

No inputs.

### `get_workspace_export`
An export's status (`pending`, `running`, `ready`, `failed`, `expired`) and, once ready, its

| Parameter | Type | Required | Description |
|---|---|---|---|

### `list_plans`
The cloud plans with their limits and prices. *Read-only* · no scope needed

No inputs.

### `get_usage`
The workspace's plan, usage this period against its limits, and whether it is suspended, plus

(`queued`, `retrying`, `failed`). *Read-only* · no scope needed

No inputs.

### `choose_free_plan`
Switch the workspace to Free (cloud mode only; local mode answers `not_available`). This

`admin`

No inputs.

### `get_billing`
Billing status: whether Stripe billing is enabled on this instance, the plan, the subscription

No inputs.

`admin`

No inputs.

### `open_billing_portal`
Return the Stripe customer portal URL, where a person changes the payment method, downloads
invoices or cancels. Works while suspended. · `admin`

No inputs.

No inputs.
