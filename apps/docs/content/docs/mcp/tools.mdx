These are the tools an agent sees once staqly is [connected over MCP](/mcp). You rarely call
them by hand (the agent picks them from your request), but this page tells you what each one
can do, which inputs it takes, and which [scope](/api/authentication#scopes) an API key needs
for it in cloud mode.

## Example: draft, preview, schedule

The most common sequence, with the arguments an agent sends:

<Steps>
<Step>
### Find the channels: `list_channels`

No inputs. Returns every connected account with its `id`, `provider`, `name` and `status`.
</Step>
<Step>
### Write the post: `create_post`

```json
{ "collection": "Product updates", "content": "v1.4 is out: schedules, channels and a calendar.", "targets": [{ "channel_id": "ch_7h2kq9xw3nbvd5yhzm6a" }, { "channel_id": "ch_q2w8n5k7r3t9y4u6i1o0", "content": "v1.4 is out." }] }
```

The post is created as `draft`, with a shorter text of its own on the second channel.
</Step>
<Step>
### Check it: `preview_post`

```json
{ "post_id": "post_oalirbz67y4m4cqxq5dw" }
```

Returns the text each channel will carry and what its provider objects to (too long, media
missing). Fix the post with `update_post`.
</Step>
<Step>
### Put it on the calendar: `schedule_post`

```json
{ "post_id": "post_oalirbz67y4m4cqxq5dw", "publish_at": "2026-11-03T09:00:00Z" }
```

Or `publish_post` to send it now. A failed channel is retried alone with `retry_target`.
</Step>
</Steps>

A full walkthrough: [Let an agent fill a collection](/cookbook/agent-fills-a-collection).

## Conventions

- Scopes only matter in **cloud mode** (with an API key); in Staqly Community Edition the access token
  gives every tool.
- Tools marked *read-only* are annotated as such for clients that care; tools marked
  *destructive* delete or invalidate something (data, a key, a secret).
- Collection inputs accept an ID (`col_qjuybkx6355nz4no6pqk`) **or** the exact name.
- Tools and REST go through the same authorization checks. Most REST operations have a tool;
  these have none: the browser flows (sign-in, sign-out, setup, redeeming a device link or a
  connect link, the OAuth start and callback of a channel, a Telegram connect code), cloud accounts
  (sign-in methods, notification settings, members and invitations: people are managed by people),
  the local access token, recovery key
  rotation (dashboard session only), developer app registration (`PUT /v1/providers/{id}/app`),
  the agent list (`/v1/agents`), the list of workspace exports (`GET /v1/workspace/exports`), job
  details (`GET /v1/jobs/{id}`, `/stats`, `/cancel`), the design editor (`/v1/media-projects`,
  `/v1/design/brand`, `/v1/ai`, `/v1/stock/photos`, `POST /v1/media/{id}/replace`), the dashboard assistant
  (`/v1/assistant`) and the billing extras (details, add-ons, X post bundles).
- A suspended workspace (trial or paid period ended unpaid) can call read-only tools plus `revoke_session`,
  `revoke_api_key`, `create_device_link`, `start_workspace_export`,
  `start_billing_checkout`, `open_billing_portal`, `delete_workspace` and `purge_post`; other
  tools answer with `plan_expired`, like REST.

## Posts

### `list_posts`

| `publish_before` | string | No | RFC3339 or YYYY-MM-DD, exclusive |
| `sort` | string | No | Publish_asc (default), publish_desc, created_desc, created_asc |

### `create_post`
Create a post in a collection: content, media (ids from upload_media), targets (one per channel, each with an optional content override and settings: the provider's settings_fields from list_providers, as strings, e.g. X reply_settings, made_with_ai, thread_finisher, reposters as comma-separated channel ids), tags, metadata. status draft (default) or scheduled (needs publish_at, RFC3339 in the future, and a target); publish_now true publishes at once. repeat_every (1d to 6d, 1w, 2w, 1mo) schedules a copy that long after each time the post is published. thread: follow-up parts (content, media, delay_seconds) published as replies under the post on platforms that take replies (X); your own automation receives them with the request. · `posts:write`

| Parameter | Type | Required | Description |
|---|---|---|---|

| `metadata` | object | No | Free JSON for your own use |
| `publish_at` | string | No | RFC3339, in the future |
| `publish_now` | boolean | No | Publish right away |
| `repeat_every` | string | No | Repeat after publishing: 1d to 6d, 1w, 2w or 1mo (empty: no repeat) |
| `status` | string | No | Draft (default) or scheduled |
| `tags` | string[] | No |  |
| `targets` | object[] | No |  |
| `thread` | object[] | No | Replies published under the post, in order (at most 25): `content`, `media`, `delay_seconds` |

### `update_post`

A published post is refused (duplicate it). Pass expected_version to refuse the edit when someone changed it meanwhile. · `posts:write`

| Parameter | Type | Required | Description |
|---|---|---|---|
| `collection` | string | No |  |

| `metadata` | object | No |  |
| `post_id` | string | <Required /> | Post ID (post_...) |
| `publish_at` | object | No | RFC3339 in the future, or an empty string to clear it (back to a draft) |
| `repeat_every` | string | No | 1d to 6d, 1w, 2w or 1mo; an empty string stops repeating |
| `tags` | string[] | No |  |
| `thread` | object[] | No | Replaces the replies; [] clears them |
| `targets` | object[] | No | Replaces the whole list |
