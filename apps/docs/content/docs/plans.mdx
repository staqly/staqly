---
title: Plans & limits
description: See what the Free and Pro plans allow in cloud mode, how the 7-day Pro trial works and what happens when a workspace hits a limit.
---

Plans set how much each workspace may use on a **cloud-mode** instance: posts per month,
channels, storage and so on. Collections and schedules are unlimited on every plan. If you run
staqly on your own computer (local mode), plans don't apply to you: local installs are always
**Unlocked**, with no limits (usage is still shown for information).

## Plan comparison

| Limit | Free | Pro: $30/mo |
|---|---|---|
| Posts created / month | 50 | Unlimited |
| Collections and schedules | Unlimited | Unlimited |
| Connected channels | 3 | Unlimited |
| Alerts | 2 | Unlimited |
| Webhooks | 3 | Unlimited |
| Active API keys | 1 | Unlimited |
| Storage | 1 GB | 100 GB |
| Max file size | 5 MB | 100 MB |
| Workspace data export (ZIP of collections, posts, channels, schedules, events) | Yes, without files | Yes, with files |
| Backups and activity log export | — | Yes |

Signed webhooks, MCP and full history are on every plan. Every plan can
[export its data](/self-hosting/data-export) (**Settings → Data & privacy**): on Free the
workspace ZIP is data only (`includes_media: false`), with media files listed by id, name and
type but not included. The ZIP with the media files, backups (**Settings → Backups**) and the
activity log export are Pro, trial included: on Free `GET /v1/events/export` answers
`402 plan_limit_exceeded` (limit `data_export`). Local installs always have everything. File sizes are also capped
by the operator's `MAX_UPLOAD_MB` (default 100 MB). On Free the one API key is the admin key
you get when the workspace is created (it also signs in to the dashboard); on Pro, give each
agent its own scoped key without `admin`.

## The Pro trial

1. Every new cloud workspace starts on **Pro for 7 days**, with no card.
2. Before the trial ends, upgrade ([with a card](#changing-a-workspaces-plan) when billing is enabled), or switch to Free (**Settings → Plan & usage → Switch to Free**,
   or `POST /v1/workspace/plan` with `{"plan":"free"}`, admin scope).
3. If the trial ends and the workspace was neither paid nor switched to Free, it is
   **suspended**:
   - you can still **read and export** everything (dashboard, `GET` requests, read-only MCP
     tools, the workspace export);
   - every change (new posts, publishing, channels, schedules and so on) answers
     **402 `plan_expired`**, and schedules stop running;
   - your data stays; switching to Free or paying lifts the suspension right away.

The same applies when a paid Pro period ends unpaid. `GET /v1/workspace/usage` shows
`plan_expires_at` (end of the trial or paid period, `null` = no end) and `suspended`.

## How limits are counted

- Limits apply **per workspace**: every API key of a workspace shares its plan.
- **Posts / month** counts every post created per calendar month (UTC), whether by a person in
  the dashboard, an agent over MCP or REST, a duplicate, or a schedule that fetched posts from
  your endpoint. Deleting a post does not refund it.
- When the month's posts are used up, creating one answers `402`. Publishing, scheduling and
  editing the posts you have keep working.
- Channels, alerts, webhooks, API keys and storage are counted from what currently exists; a
  disabled channel still counts.

## Checking usage

- Dashboard: **Settings → Plan & usage** ([details](/dashboard/plan-and-usage)).
- API: `GET /v1/plans` lists plans and limits (`-1` = unlimited); `GET /v1/workspace/usage`
  returns the current plan, the period (`2026-10`) and usage, plus `posts_by_status` (posts
  created this month, by their current status) and `webhook_deliveries` (`queued`, `retrying`
  and `failed` deliveries).

## What happens when you hit a limit

A request over a limit fails with **HTTP 402** and machine-readable `details`:

```json
{
  "error": {
    "code": "plan_limit_exceeded",
    "message": "The Free plan allows 50 posts per month; upgrade the workspace plan to continue.",
    "details": { "limit": "posts_per_month", "max": 50, "used": 50, "plan": "free" }
  }
}
```

`details.limit` is one of `posts_per_month`, `channels`, `alerts`, `webhooks`, `api_keys`,
`storage_bytes`, `max_upload_bytes` or `data_export`.

## Changing a workspace's plan

There are three ways a workspace changes plan:

- **Upgrade with a card** (when the operator has set up [billing with Stripe](/self-hosting/billing)):
  **Settings → Plan & usage → Upgrade to Pro** opens Stripe Checkout (`POST /v1/billing/checkout`,
  admin scope). When Stripe confirms the payment, the workspace moves to Pro until the end of the
  paid period plus 3 days of grace. **Manage billing** opens the Stripe customer portal
  (`POST /v1/billing/portal`) to change the card, download invoices or cancel. When a subscription
  is canceled or stays unpaid, Pro ends and the workspace is suspended until it pays again or
  switches to Free. `GET /v1/billing` shows the subscription status.
- **Switch to Free** yourself: **Settings → Plan & usage → Switch to Free**, or
  `POST /v1/workspace/plan` with `{"plan":"free"}` (admin scope). With a live Stripe subscription,
  cancel it in the billing portal first (`409 conflict` otherwise). Asking this endpoint for
  `pro` answers `402 payment_required`.
- **The operator sets the plan** on the server. Without `--until` the plan has no end date (this
  also ends a trial or a suspension); with `--until` the plan is comped until that date, after
  which the workspace is suspended like an unpaid one.

```bash tab="Docker"
docker exec staqly server workspaces            # id, plan, plan ends, created, name
docker exec staqly server set-plan ws_h2c5vq7nzk4mtr6pxw3e pro
docker exec staqly server set-plan ws_h2c5vq7nzk4mtr6pxw3e pro --until 2026-12-31
```

```bash tab="staqly serve"
staqly serve workspaces                         # id, plan, plan ends, created, name
staqly serve set-plan ws_h2c5vq7nzk4mtr6pxw3e pro                    # free | pro
staqly serve set-plan ws_h2c5vq7nzk4mtr6pxw3e pro --until 2026-12-31 # comp until a date
```

Every plan change is recorded as a `workspace.plan_changed` [event](/api/events#other-events)
with the reason (`stripe:active`, `operator`, `operator_comp`, `self_service`). See
[Operator CLI](/self-hosting/operator-cli) for the other server commands.

The plan table lives in `apps/api/internal/app/plans.go`, the single source of truth for
limits and for the pricing shown in the dashboard.
