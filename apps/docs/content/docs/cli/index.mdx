The `staqly` command sends AI output to staqly for review, blocks a script until a human approves
or rejects it, and lets you work through the inbox without leaving the terminal. The same binary
also runs the whole staqly server with `staqly serve`.

Pick the CLI for shell scripts, CI jobs and quick checks. Use an [SDK](/sdk/typescript) inside a
TypeScript or Python program, [MCP](/mcp) when an AI agent such as Claude Code talks to staqly
directly, and the [REST API](/api) from any other language.

## Get started

<Steps>
<Step>
### Install the binary

```bash
curl -fsSL https://raw.githubusercontent.com/staqly/staqly/main/scripts/install.sh | sh
```

The script installs the latest release for macOS or Linux (amd64, arm64) to `~/.local/bin/staqly`
and checks the download against the release's `checksums.txt`. Make sure `~/.local/bin` is on
your `PATH`, then confirm it works:

```bash
staqly version
```

</Step>
<Step>
### Start a server (or point to one)

If staqly isn't running yet, start it on this computer. It needs no Docker and no account:

```bash
staqly serve
```

The API and MCP endpoint listen on `http://localhost:3333`, the dashboard on
`http://localhost:8080`. Leave it running and open a second terminal.

Already running staqly in Docker or in the cloud? Skip this step. For a cloud server, save its
URL and key once with `staqly login --url https://staqly.example.com --key stk_...`.

</Step>
<Step>
### Push an item and wait for a decision

```bash
staqly collections create Deploys
staqly push Deploys --title "Deploy v1.4" --content "Ship the new billing page?"
```

`push` creates the item and waits. It returns as soon as someone approves or rejects it.

</Step>
<Step>
### Decide

Open the dashboard at `http://localhost:8080`, or review from another terminal:

```bash
staqly inbox
```

Press <Kbd>a</Kbd> to approve or <Kbd>r</Kbd> to reject with feedback. The waiting `push` prints
the decision and exits `0` when approved or `2` when rejected, so a script can act on it.

</Step>
</Steps>

## Other ways to install

**Windows.** Download the `.zip` for your CPU from the
[releases page](https://github.com/staqly/staqly/releases) and put `staqly.exe` on your `PATH`.

**A specific version or folder.** The install script reads two environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `STAQLY_VERSION` | latest release | Release tag to install, e.g. `v0.2.0` |
| `STAQLY_INSTALL_DIR` | `~/.local/bin` | Where to put the binary |

```bash
curl -fsSL https://raw.githubusercontent.com/staqly/staqly/main/scripts/install.sh | STAQLY_VERSION=v0.2.0 sh
```

**From a checkout of the repository.** Requires Go and Node:

```bash
make dashboard   # embeds the dashboard for `staqly serve`
cd apps/cli
make build       # → apps/cli/bin/staqly
make install     # → $GOBIN, or ~/go/bin
```

**Shell completion:**

```bash
source <(staqly completion bash)        # or zsh
staqly completion fish > ~/.config/fish/completions/staqly.fish
```

## Run the server

`staqly serve` runs the API, MCP endpoint, background workers and dashboard in one process.

```bash
staqly serve                                         # dashboard on this computer only
staqly serve --expose                                # dashboard reachable from phones and tablets
staqly serve --data ~/staqly-data --port 4333 --dashboard-port 9090
```

| Flag | Default | Meaning |
|---|---|---|
| `--data` | `~/.local/share/staqly` (or `STAQLY_DATA_DIR`) | Folder for the SQLite database and uploads |
| `--port` | `3333` | API and MCP port, always bound to `127.0.0.1` |
| `--dashboard-port` | `8080` | Dashboard port |
| `--expose` | off | Serve the dashboard on all network interfaces; each browser signs in once with a link from `staqly serve connect-link` |

With a subcommand, `staqly serve` runs an operator task against the same data instead:
`connect-link`, `backup <file>`, `workspaces`, `stats`, `recovery-key` and `set-plan`. See
[Run the binary](/self-hosting/binary) and [Operator CLI](/self-hosting/operator-cli).

## Connect to a server

By default the CLI talks to a local server at `http://localhost:3333` without a key. To use
another server, pass flags, set environment variables, or save a profile.

| Setting | Flag | Environment | Profile field | Default |
|---|---|---|---|---|
| API base URL | `--api-url` (alias `--url`) | `STAQLY_API_URL` | `url` | `http://localhost:3333` |
| API key | `--key` | `STAQLY_API_KEY` | `key` | none (local mode is keyless) |
| Profile | `--profile` | `STAQLY_PROFILE` | `current` | `default` |
| Config file | none | `STAQLY_CONFIG` | none | `$XDG_CONFIG_HOME/staqly/config.json`, else `~/.config/staqly/config.json` |

The first one set wins, in this order: **flag, environment variable, selected profile, default**.

<Callout type="warn" title="--url means something else for some commands">
`items create` / `push` (the item's link), `webhooks create` and `webhooks update` (the receiver URL) and
`watchers create` (the feed or page URL) use `--url` for their own field. Set the API address
with `--api-url` or `STAQLY_API_URL` there.
</Callout>

### Save servers as profiles

```bash
staqly login                                                  # local server, keyless → profile "default"
staqly login --url https://staqly.example.com --key stk_... --profile work
echo "$KEY" | staqly login --url https://staqly.example.com --key - --profile ci
staqly profiles                 # list (keys masked); * marks the current one
staqly profiles use work        # switch
staqly status --profile ci      # use a profile for one command
staqly logout --profile ci      # remove a profile
```

`login` checks the credentials against `GET /v1/session` before saving (skip with
`--no-verify`), writes the config file (folder `0700`, file `0600`) and makes the profile
current. Without `--key` it uses `STAQLY_API_KEY` or asks for the key at a hidden prompt.

### How keys are protected

- A key stored in a profile is only sent to **that profile's own URL**. If `--api-url` or
  `STAQLY_API_URL` points somewhere else, the CLI sends no key and prints a note. Pass `--key` or
  `STAQLY_API_KEY` to authenticate against the other server.
- The CLI warns when a key would travel over plain `http://` to a host other than `localhost`.
  Use `https://` for remote servers.

## Output formats

- Human-readable tables by default. Colors only appear on a terminal; `NO_COLOR=1`, `TERM=dumb`
  or `--no-color` turn them off.
- `--json` prints the API response unchanged. Streaming commands (`events tail --follow`,
  `inbox --watch`) print one JSON object per line (NDJSON).
- With `--json`, errors go to stderr as
  `{"error":{"code","status","message","fields","details","retry_after_seconds"}}`.
- Text from the server (titles, content, metadata, error messages) is treated as untrusted.
  Human output strips control characters, ANSI / OSC escape sequences and Unicode bidi overrides
  before printing. `--json` keeps the data intact but writes C1 controls and bidi overrides as
  `\uXXXX` escapes, so it is still safe to view in a terminal.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success. With `push` / `--wait`: **approved** |
| `1` | Error: API, network, failed confirmation, or some items of a multi-item command failed |
| `2` | `push` / `--wait`: **rejected** |
| `3` | `push` / `--wait`: **timed out** (still pending) or the item **expired** |
| `4` | `push` / `--wait`: the item left `pending` with another status (e.g. a custom action, archived) |
| `64` | Usage error: unknown command or flag, missing arguments |
| `130` | Interrupted (<Kbd>Ctrl</Kbd>+<Kbd>C</Kbd>). `--follow` and `--watch` exit `0` on Ctrl-C |

## Error messages

The CLI turns API errors into plain-language hints:

| Status | What it tells you |
|---|---|
| `401` | Pass `--key` or run `staqly login` |
| `402` | The plan limit you hit, with usage and maximum |
| `403 not_local` | A keyless request came from another machine |
| `403` (scope) | Which scope the key is missing |
| `409` | The item changed or was already decided |
| `422` | Each invalid field |
| `429` | How long to wait (`Retry-After`) |

When the server can't be reached, the error names the URL it tried.
