---
title: Cursor
description: Add staqly to Cursor so its agent saves output for your review and waits for your approval.
---

Connect Cursor to staqly as an MCP server, and Cursor's agent can create collections, save
drafts and images as items, and stop to ask for your approval before a risky step. Do this
once per machine (`~/.cursor/mcp.json`) or once per repository (`.cursor/mcp.json`).

## Connect to local staqly

<Steps>
<Step>

### Start staqly

Run `staqly serve` (or the [Docker image](/self-hosting/docker)). See the [Quickstart](/quickstart).

</Step>
<Step>

### Add the MCP server

In local mode, no key is needed. Write the config with the CLI:

```bash
mkdir -p .cursor && staqly mcp config cursor --snippet > .cursor/mcp.json
```

or create it yourself:

```json title=".cursor/mcp.json"
{ "mcpServers": { "staqly": { "url": "http://localhost:3333/mcp" } } }
```

Use `~/.cursor/mcp.json` instead to have staqly in every project.

</Step>
<Step>

### Check the connection

Open **Cursor Settings → MCP**. `staqly` should show a green dot and its tools. If it doesn't,
toggle it off and on, or see [Other MCP clients](/agents/other-mcp-clients#check-the-connection-with-curl)
to test the endpoint with curl.

</Step>
</Steps>

### STDIO (Docker only)

If you run staqly with Docker, you can use STDIO instead of HTTP. It runs `mcp-stdio` inside
the `staqly` container, so it does not work with `staqly serve`:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "staqly": { "type": "stdio", "command": "docker", "args": ["exec", "-i", "staqly", "mcp-stdio"] }
  }
}
```

## Connect to a cloud instance

Create a key for Cursor under **API keys** in the sidebar, e.g. with
`collections:read items:read items:write`, export it, and reference it from the config.
Cursor expands `${env:STAQLY_API_KEY}`, so the key stays out of the file:

```bash
export STAQLY_API_KEY=stk_...
staqly mcp config cursor --snippet > .cursor/mcp.json   # with a cloud CLI profile
```

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "staqly": {
      "url": "https://staqly.example.com/mcp",
      "headers": { "Authorization": "Bearer ${env:STAQLY_API_KEY}" }
    }
  }
}
```

Cursor reads the variable from the environment it was started in, so start it from that shell
(`cursor .`) or set the variable for your login session.

## Ask for approval before acting

Create an **Approvals** collection once (in the dashboard, or ask the agent), then add a
project rule so the agent always asks you before doing something that is hard to undo:

```md title=".cursor/rules/staqly.mdc"
---
description: Ask for human approval in staqly before side effects
alwaysApply: true
---

Before any action with side effects (running a migration, deploying, sending an email or
message, publishing, deleting data, spending money):

1. Call `create_item` with `collection: "Approvals"`, a short title and, as content, the
   exact command, diff or text you are about to run or send.
2. Call `await_decision` with the item id. Repeat while it is still pending.
3. Continue only if the status is `approved`, and use the item's content (I may have edited it).
   If it is `rejected`, stop and read the feedback.
4. After acting, call `report_result` with `completed` or `failed`.
```

The decision arrives in the staqly Inbox, and on your phone if you set up
[notifications](/automation/notifications). The full pattern is in
[Approval gate](/cookbook/approval-gate).
