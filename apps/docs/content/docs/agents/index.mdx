To save output in staqly, an agent or automation has to talk to it. Coding agents such as
Claude Code, Codex and OpenCode use **MCP** (Model Context Protocol, the standard way to give
an AI agent tools). Automations and scripts use the **REST API**. Both go through the same
services and the same permission checks, so they can do the same things.

The [`staqly` CLI](/cli/commands) can also print the right MCP setup for you:
`staqly mcp config claude` (or `codex`, `opencode`, `cursor`, `windsurf`).

## Endpoints

| Protocol | For | Endpoint |
|---|---|---|
| **MCP**, Streamable HTTP (recommended) | coding agents | `http://localhost:3333/mcp` |
| **MCP**, STDIO | clients that only support STDIO; needs Docker | `docker exec -i staqly mcp-stdio` |
| **REST** | automations and scripts | `http://localhost:3333/v1/...` |

## Which MCP transport?

Use Streamable HTTP unless your client only supports STDIO. HTTP works with both
`staqly serve` and Docker; STDIO runs a helper inside the `staqly` Docker container.

| Aspect | Streamable HTTP | STDIO |
|---|---|---|
| Endpoint | `http://localhost:3333/mcp` | `docker exec -i staqly mcp-stdio` |
| Works with `staqly serve` | Yes | Not out of the box: needs Docker, or [building `mcp-stdio` from source](/agents/other-mcp-clients#stdio-details) |
| Works with a remote / cloud instance | Yes (bearer API key) | No: it opens the database inside the container |
| Sessions | Stateless: every request is authenticated on its own | One process per agent session |
| Recommended | ✔ | When your client only supports STDIO |

<Callout type="warn" title="STDIO: use -i, never -t">
`docker exec -i` keeps stdin open for the protocol. Adding `-t` allocates a TTY and breaks
the JSON-RPC stream.
</Callout>

## Permissions in cloud mode

In local mode, every agent on your computer has full access. In **cloud mode**, MCP requires
an API key and enforces its scopes: a read-only key cannot write, `approve_item` /
`reject_item` need `items:review`, custom actions need `actions:execute`. `/mcp` accepts only
bearer keys, never browser cookies. See [MCP tools](/mcp/tools) for the scope of every tool
and [Authentication & scopes](/api/authentication) for creating keys.
