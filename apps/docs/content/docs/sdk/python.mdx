---
title: Python SDK
description: Write, schedule and publish posts, connect channels and react to webhooks from Python code, sync or async.
---

`staqly` is the official Python client for staqly. Use it when your agent, script or web app is
written in Python and should write posts, put them on the calendar, publish through your own
automation or react to webhooks. For shell scripts and cron pick the [CLI](/cli), for AI agents
that speak MCP use the [MCP server](/mcp), and in TS/JS use the [TypeScript SDK](/sdk/typescript).

It offers a sync `Staqly` and an async `AsyncStaqly` client with identical APIs, built on
`httpx`, with typed pydantic v2 models checked against the API's OpenAPI contract. Requires
Python 3.10 or newer.

## Get started

<Steps>
<Step>
### Install the package

```bash
pip install staqly        # or: uv add staqly
```

</Step>
<Step>
### Start staqly

Run a server on your computer with [`staqly serve`](/cli#run-the-server) (or Docker) and give
the SDK its access token, which staqly prints at start, in `STAQLY_API_KEY`:

```bash
export STAQLY_API_KEY=$(staqly serve token)   # Docker: $(docker exec staqly server token)
```

</Step>
<Step>
### Connect a channel, write a post, publish it

```python title="publish.py"
from staqly import Staqly

with Staqly() as staqly:  # http://localhost:3333, the token from STAQLY_API_KEY
    channel = staqly.channels.connect(provider="custom", name="My publisher")
    staqly.collections.create("Product updates")

    post = staqly.posts.create(
        "Product updates",
        content="v1.4 is out: schedules, channels and a calendar.",
        targets=[{"channel_id": channel.id}],
        publish_now=True,
    )

    done = staqly.posts.wait_for_published(post.id)  # returns when every channel settled

    for t in done.targets:
        print(t.channel_name, t.status, t.external_url or t.error)
```

</Step>
<Step>
### Watch it in the dashboard

Open `http://localhost:8080`: the post is on the **Schedule** page and in **Posts**, with a
status per channel.

</Step>
</Steps>

## Configure the client

```python
import httpx
from staqly import Staqly

staqly = Staqly(
    base_url="https://app.staqly.ai",  # default: $STAQLY_API_URL, then http://localhost:3333
    api_key="stk_...",  # default: $STAQLY_API_KEY; "" = ignore the env var
    timeout=60.0,  # seconds per request (or an httpx.Timeout)
    max_retries=2,  # retries for 408/429/5xx/network errors
    default_headers={"X-Team": "growth"},
    user_agent="my-agent/1.0",  # appended to "staqly-sdk-python/<version>"
    http_client=httpx.Client(proxy="http://proxy:8080"),  # your own client/transport
)
```

`api_key` is an API key in [cloud mode](/local-vs-cloud) (`stk_...`), or the Community Edition's access
token (`stk_local_...`); both default to `STAQLY_API_KEY`. Use the client as a context manager
(`with Staqly() as staqly:`), or call `staqly.close()`, to release connections.

Every method accepts `request_options=` for per-request overrides:

```python
staqly.posts.list(status="scheduled", request_options={"timeout": 5, "max_retries": 0})
staqly.posts.create("Posts", content="x", request_options={"idempotency_key": f"job-{job_id}"})
```

`staqly.health()` checks liveness, `staqly.ready()` checks readiness, and `staqly.whoami()`
returns the server mode, the workspace and the calling principal with its scopes. The
[reference](#reference) below lists every resource and method.

## Work with posts

```python
# a draft with a text of its own on one channel (x and publisher are channels from channels.list())
post = staqly.posts.create(
    "Product updates",  # ID or exact name
    content="Three days, every avatar half price.",
    media=[media.id],  # from staqly.media.upload
    targets=[
        {"channel_id": x.id, "content": "Three days. Half price."},
        {"channel_id": publisher.id},  # "settings": {...} sets the provider's per-post fields
    ],
    tags=["sale"],
    metadata={"campaign": "spring"},
)

staqly.posts.preview(post.id)  # the text per channel and what each platform objects to
staqly.posts.schedule(post.id, "2026-11-03T09:00:00Z")  # onto the calendar
staqly.posts.cancel(post.id)  # back to draft
staqly.posts.publish(post.id)  # now (202: a job does the work)
staqly.posts.retry_target(post.id, x.id)  # one failed channel again
staqly.posts.update(post.id, content="Fixed", expected_version=post.version)  # ConflictError when someone edited it
copy = staqly.posts.duplicate(post.id)  # a new draft; published posts are read-only

# list, search and page through everything
staqly.posts.list(status="scheduled", publish_after="2026-11-02", publish_before="2026-11-09")  # the calendar
staqly.posts.search("half price", collection_id=post.collection_id)

for p in staqly.posts.iterate(channel_id=x.id, status="published"):
    print(p.content)

staqly.posts.history(post.id)  # its events, newest first
staqly.posts.tags()  # every tag with its count
```

## Channels and schedules

```python
providers = staqly.providers.list()  # the catalog: auth, status, limits, fields
# your own automation; token platforms take their credentials in `fields` once they are available
publisher = staqly.channels.connect(provider="custom", name="My publisher")
staqly.channels.test(publisher.id)  # against the platform; marks needs_reconnect on failure
staqly.channels.disable(publisher.id)  # or enable(), update(id, name=..., settings=...)

schedule = staqly.schedules.create(
    "Product updates",
    name="Weekday mornings",
    kind="recurring",
    rule={"times": ["09:00"], "weekdays": [1, 2, 3, 4, 5], "tz": "Europe/Warsaw"},
    channels=[publisher.id],
    pick="next",
    source="agent",
)
staqly.schedules.run(schedule.id)  # now; the regular next run is unchanged
```

OAuth platforms need a person in a browser: `channels.oauth_start("x")` returns the platform's
sign-in URL to open, and the browser lands on the dashboard when done; `channels.create_link()`
makes a connect link for someone without access. See [Developer apps](/channels/developer-apps).

## Wait for a post to settle

```python
from staqly import WaitTimeoutError

try:
    post = staqly.posts.wait_for_published(post_id, timeout=30 * 60)  # seconds, default 10 min

    if post.status == "failed":
        for t in post.targets:
            if t.status == "failed":
                print(t.channel_name, t.error)
except WaitTimeoutError as e:
    print("still publishing", e.post)
```

`wait_for_published` polls the post until it is `published` or `failed` (every 2 seconds;
`poll_interval` changes it, `on_poll` is called after every check). For
long-running services, push beats waiting: subscribe a [webhook](/automation/webhooks) to
`post.published` and `post.failed`.

## Be your own publisher

A channel on [your own automation](/channels/your-own-automation) hands posts to your code:

```python
for w in staqly.work.list():
    if w.kind == "target":
        try:
            url = publish_somewhere(w.post, w.channel)
            staqly.posts.report_result(w.post.id, w.channel.id, status="published", url=url)
        except Exception as e:
            staqly.posts.report_result(w.post.id, w.channel.id, status="failed", error=str(e))
    else:
        # a schedule found nothing to publish: write drafts into w.collection
        staqly.posts.create(w.collection.id, content=draft_one())
```

`work.list()` is `GET /v1/work`. With a webhook on `post.publish_requested` you get the same
request pushed to you.

## Verify webhooks

Every webhook delivery is signed with the webhook's secret (`whsec_...`). `verify_webhook` checks
the `X-Staqly-Signature` and `X-Staqly-Timestamp` headers, rejects timestamps more than 300 s
away, and returns the parsed event. It raises `WebhookVerificationError` otherwise.

```python title="app.py"
import os

from fastapi import FastAPI, Request, Response
from staqly.webhooks import WebhookVerificationError, verify_webhook

app = FastAPI()


@app.post("/hooks/staqly")
async def staqly_hook(request: Request) -> Response:
    body = await request.body()  # the raw body, exactly as received

    try:
        event = verify_webhook(os.environ["STAQLY_WEBHOOK_SECRET"], body, request.headers)
    except WebhookVerificationError:
        return Response("invalid signature", status_code=400)

    if event.type == "post.publish_requested":
        await publish_myself(event.data["post"], event.data["channel"])

    return Response("ok")
```

- Always pass the **raw** body (`bytes`). JSON that was parsed and serialized again will not match.
- `headers` is any mapping (Starlette, Flask and Django request headers work).
- `tolerance=` changes the time window in seconds (`0` disables it).
- Deliveries are at-least-once and can arrive out of order: de-duplicate on `event.id` (also
  sent as `X-Staqly-Event-Id`) and order by `event.created_at`
  ([Delivery guarantees](/automation/webhooks#delivery-guarantees)).
- `is_valid_webhook()` returns a boolean instead of raising; `compute_webhook_signature()` helps
  you test your handler. The same functions verify a
  [schedule endpoint](/automation/schedules#call-an-endpoint-source-endpoint) request with the
  schedule's `endpoint_secret`.

## Handle errors

Every error subclasses `staqly.StaqlyError`. HTTP errors subclass `APIError` and carry `status`,
`code`, `message`, `fields`, `details`, `request_id`, `body` and `response`. `request_id` is the
server's `X-Request-Id`; include it in bug reports.

| Class | When |
|---|---|
| `BadRequestError` | 400 |
| `AuthenticationError` | 401 missing, invalid or revoked key |
| `PlanLimitError` | 402 `plan_limit_exceeded`, with `.limit`, `.max`, `.used`, `.plan` |
| `PermissionDeniedError` | 403 missing scope, or the action needs a dashboard session |
| `NotFoundError` | 404 |
| `ConflictError` | 409, e.g. the post is published, the version changed (`post_changed`), the platform is `soon` |
| `GoneError` | 410 |
| `PayloadTooLargeError` / `UnsupportedMediaTypeError` | 413 / 415 |
| `ValidationError` | 422, with `.fields` (a target over its provider's limit is keyed `targets.<channel_id>.content`) |
| `RateLimitError` | 429, with `.retry_after` |
| `InternalServerError` | 5xx |
| `APIConnectionError` / `TimeoutError` | no response / request timed out (`TimeoutError` is also the built-in `TimeoutError`) |
| `WaitTimeoutError` | `wait_for_published` or `wait_for_workspace_export` gave up (`.id`, `.waited`, `.post`); also a built-in `TimeoutError` |
| `ExportFailedError` | a workspace export ended `failed` or `expired` (`.job`) |
| `WebhookVerificationError` | bad signature or timestamp |

```python
from staqly import ConflictError

try:
    staqly.posts.update(post_id, content="x", expected_version=3)
except ConflictError:
    pass  # someone edited the post meanwhile; reload it
```

## Retries, timeouts and idempotency

- Requests that fail with 408, 429, 500, 502, 503, 504, a network error or a timeout are retried
  up to `max_retries` times (default 2) with exponential backoff and jitter. A `Retry-After` of
  60 s or less is honored; a longer one raises `RateLimitError` right away.
- Every `POST`, `PATCH` or `DELETE` with a JSON body gets an automatic `Idempotency-Key`, reused
  across its retries, so a retry never applies the request twice. Set
  `request_options={"idempotency_key": "tip-2026-10-20"}` to choose the key yourself. JSON bodies are compared by
  content (key order and spacing don't matter), so a key can be shared with the TypeScript SDK.
- Multipart uploads are retried only on 429.
- `timeout` (default 60 s) applies to each attempt.

## Use the async client

`AsyncStaqly` has the same API. Await the methods, use `async for` on iterators, and use
`async with AsyncStaqly()` or `await staqly.aclose()` instead of `close()`:

```python
import asyncio

from staqly import AsyncStaqly


async def main() -> None:
    async with AsyncStaqly() as staqly:
        post = await staqly.posts.create("Drafts", content="Hello", targets=[{"channel_id": channel_id}])
        await staqly.posts.publish(post.id)
        done = await staqly.posts.wait_for_published(post.id)
        print(done.status)

        async for p in staqly.posts.iterate(status="published"):
            print(p.content)


asyncio.run(main())
```

## Reference

Every method accepts `request_options=` (`timeout`, `max_retries`, `idempotency_key`, `headers`).
Methods that return a list return a Python `list`; `list()` on paginated endpoints (`posts`,
`events`, `jobs`) returns a page with `.data` and `.next_cursor`, and `iterate()` walks every page.
