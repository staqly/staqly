title: Discord
description: Publish to Discord channels through the server's own bot, with text, pictures, videos and replies. What to register in the Discord Developer Portal, and the webhook way in for servers without a bot.
---

Staqly publishes to **Discord** through a bot: the person adds the server's Discord application to
a Discord server with OAuth2, and that **Discord server** becomes a staqly channel. Connect as many
Discord servers as you like; each post picks the Discord channels it goes to. Messages go out as
the bot with `POST /channels/{id}/messages`, pictures and videos as attachments. A published target
links to the message.

A staqly server without a Discord bot connects Discord through a
[channel webhook](#through-a-webhook) instead, one Discord channel per staqly channel.

## What whoever runs the server sets up

A **Discord application with a bot**, registered once per server. Its keys and the bot's token go
into the server's environment, the same way locally and in the cloud. A workspace can't bring its own
Discord app: the bot that posts is the server's.

<Steps>
<Step>

### Create the application

In the [Discord Developer Portal](https://discord.com/developers/applications), **New
Application**, name it (the bot shows with this name and icon on every message). Then:

| Where | What |
|---|---|
| **OAuth2 → Redirects** | your dashboard's `/channels/callback/discord`, for example `https://staqly.example.com/channels/callback/discord` (locally `http://localhost:8080/channels/callback/discord`) |
| **OAuth2** | copy the **Client ID** and **Client Secret** (Reset Secret) |
| **Bot** | **Reset Token** and copy the bot's token. **Public Bot** on, so people other than you can add it. No privileged gateway intents are needed: staqly never reads messages, it only sends them |

</Step>
<Step>

### Give staqly the keys

Put all three in the server's environment and restart it:

```bash title=".env"
PROVIDER_DISCORD_CLIENT_ID=your-client-id
PROVIDER_DISCORD_CLIENT_SECRET=your-client-secret
PROVIDER_DISCORD_BOT_TOKEN=your-bot-token
```

- **Docker:** `docker run ... --env-file .env ghcr.io/staqly/staqly:latest`, or `-e PROVIDER_DISCORD_CLIENT_ID=...`.
- **Binary:** export them in your shell, then run `staqly serve` or `staqly service install` (the
  service keeps `PROVIDER_*` settings).

Until all three are set, **Channels → Add channel → Discord** connects a webhook instead.
`PROVIDER_DISCORD_ENABLED=false` hides the bot; `PROVIDER_DISCORD_WEBHOOK_ENABLED=false` the
webhook. **Settings → System → Platforms** tells which of the three is missing and
whether Discord takes the keys.

A channel stores only its Discord server's id: the bot's token is read from the environment each
time, so a new token for the same bot keeps every channel working.

</Step>
</Steps>

## Connect a Discord server

**Channels → Add channel → Discord**, then **Connect with Discord** opens discord.com, where the
person picks the Discord server and allows the bot. They need the **Manage Server** permission
there. The channel shows the Discord server's name and icon; connecting the same server again
reconnects it. For another Discord server, connect again and pick that one. The bot joins with these
permissions:

| Permission | Why |
|---|---|
| View Channels | See the channels to post in |
| Send Messages | Post |
| Embed Links | Show link previews |
| Attach Files | Send pictures and videos |
| Read Message History | Reply to the post's message |
| Send Messages in Threads, Create Public Threads | Post in threads |

The bot can post in every channel its role may see and send messages in. For a private channel,
give the bot's role access to it in the channel's **Permissions**.

## Limits

| | |
|---|---|
| Text | 2,000 characters |
| Media | up to **10** pictures and videos per message |
| Files | **10 MB** each unless the Discord server is boosted (Discord refuses larger ones) |

## Settings per post

| Setting | What it does |
|---|---|
| **Discord channels** (`channel`, required) | Up to 10 text or announcement channels of the Discord server, ids or `#names`, comma-separated: one message in each. The dashboard picks **#general** for a new post when the server has one; pick others from the list (`GET /v1/channels/{id}/options/channel`, MCP `list_channel_options`), which shows the channels the bot may post in. When one channel refuses after others took the post, the target fails naming where it went, and is not retried (it would post twice) |

## Comments

A post's [thread](/concepts#threads-comments-under-a-post) goes out as **replies** to the post's
message in every channel it went to, each under the one before, after its delay. A reply whose
message was deleted in the meantime still goes out, as a plain message.

## When publishing fails

| Discord says | Staqly does |
|---|---|
| The bot was removed from the Discord server, or the server is gone | Marks the channel **Needs reconnect** and fails the target: add the bot again from the row's menu |
| The bot token is wrong (401) | Marks the channel **Needs reconnect**: whoever runs the server sets `PROVIDER_DISCORD_BOT_TOKEN` to the bot's current token |
| The bot can't post in the post's channel (Missing Access, Missing Permissions), or the channel is gone | Fails the target only: the Discord server stays connected. Give the bot's role access, or pick another channel |
| Rate limit (429) | Retries after the time Discord asks for, through the job queue |
| Discord unavailable (5xx) | Retries through the job queue (after 1, 5, then 15 minutes) |
| A file too large, a refused message | Fails the target with Discord's reason; retrying would not help, so it does not |
| The answer never came back (a dropped connection) | Fails the target saying the message **may have been published**: sending again could post twice. Check the channel before you retry |

## Through a webhook

On a staqly server without a Discord bot, **Channels → Add channel** shows **Discord webhook**
(provider `discord_webhook`). It needs nothing from whoever runs the server: anyone who may manage a
Discord channel makes a webhook there in a minute. Every Discord channel connected before staqly had
the bot is such a webhook channel, and keeps working as it was.

<Steps>
<Step>

### Make the webhook

In Discord, open the channel's settings (the gear next to its name), or **Server Settings**, then
**Integrations → Webhooks → New Webhook**. Pick the channel, give the webhook a name and a picture
(the posts show them as the author), then **Copy Webhook URL**. You need the **Manage Webhooks**
permission.

</Step>
<Step>

### Connect it in staqly

**Channels → Add channel → Discord webhook**, then paste the **Webhook URL**
(`https://discord.com/api/webhooks/<id>/<token>`). Staqly asks Discord for the webhook and shows its
name and picture; the URL is stored sealed and never shown again. Connecting the same webhook again
reconnects the existing channel. For several Discord channels, make one webhook in each.

</Step>
</Steps>

Messages go out with `POST /webhooks/{id}/{token}?wait=true`, with the same limits as the bot.

| Setting | What it does |
|---|---|
| **Forum post title** (`thread_name`) | Needed when the webhook belongs to a **forum** (or media) channel: the post starts a forum post with this title, up to 100 characters. Leave it empty for a text channel |

A webhook cannot reply to a message in a text channel, so a post's comments go out only under a
**forum post**: give the post a forum post title and each comment follows in the forum post's
thread. On a text channel the first comment fails with that reason and the rest are skipped; the
post itself stays up.

| Discord says | Staqly does |
|---|---|
| Unknown webhook (deleted, or its URL was reset) | Marks the channel **Needs reconnect** and fails the target: make a new webhook and reconnect the channel with its URL |
| Rate limit (429) or Discord unavailable (5xx) | Retries through the job queue (after 1, 5, then 15 minutes) |
| A forum channel without a forum post title, a file too large, a refused message | Fails the target with the reason; retrying would not help, so it does not |
| The answer never came back (a dropped connection) | Fails the target saying the message **may have been published**: webhooks take no idempotency key, and sending again could post twice. Check the channel before you retry |

The webhook's token is part of its URL, so staqly never puts the URL in error messages or logs.
